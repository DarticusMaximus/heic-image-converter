What the build.rs hunks show, against VENDORED.md § "Edited: build.rs":
- `const VERSION: &str = "26.10.1"` is gone; the release comes from the manifest.
- `download_and_extract()` and `archive_name()` are replaced by
  `resolve_from_manifest()`, `load_archive()` and `verify_library()`, all routed
  through the added `build_support` module.
- `HEIF_BINARIES_DIR` is still used as-is when set.
- The archive's SHA-256 is verified before extraction (the `verify_checksum`
  call in `resolve_from_manifest`), and the extracted library is hashed on every
  run (`verify_library`).
- A `committed: true` archive is local-only: `load_archive` reads it from
  `../heif-bundles/` and falls back to the pinned URL only for an artifact the
  manifest marks `committed: false`.
- The replacement's failure message names the archive, both hashes and
  `scripts/heif-artifacts.sh fetch <archive>`.

Unchanged, as VENDORED.md claims: `main()`, `emit_link_directives()` (including
`link_compiler_rt_builtins()` for the macOS workaround) and `generate_bindings()`.
They appear in both files and are outside every hunk; the only hunk that touches
one of them is `link_compiler_rt_builtins`'s `Command` chain, reformatted by
rustfmt with no behaviour change (`.arg(...)`/`.output()` split across lines).

== 4. The two added files ==

file to diff against, which is why `diff -rq` reports it as present in one side

hex SHA-256, checksum verification, local-vs-fetch policy) and is compiled by

`VENDORED.md` — only in the vendored tree, 120 lines. This is the fork record
itself: upstream version and commit, the tarball hash, the two edits, the two
additions, the archive release, and the re-vendor procedure.
